# 3D 명함 생성기 — 작업 메모

원본: Claude 대화 아티팩트 "SECO 3D 명함 생성기" (2026-11-03) → 이 저장소로 이관.

## 현재 사양
- 동료 목록을 만들고 한 명씩 또는 전체를 STL로 내보낸다. 목록은 브라우저 localStorage(`seco3dcard.v4`)에 저장
- 명함 앞면: 이름 / 직급 / 팀 / SECO 로고 + 우하단 QR. 연락처는 QR 안의 vCard로 들어감
- QR에 넣을 항목(휴대폰·회사전화·이메일·팀직급·팩스·주소)을 체크박스로 선택
- 크기 100/120/150% (86×54mm 기준), 판 두께·글자 높이·모서리 반경·획 굵기 조절
- 엑셀 붙여넣기(탭/쉼표)로 여러 명 일괄 입력. 전화번호 자동 포맷, 이메일 도메인 자동 보완
- 출력물: zip 안에 `1_base` / `2_light` / `3_accent`(다색용) + `4_single`(단색용) + 출력안내 txt

## 개인정보 취급 — 중요
- 이 저장소는 **공개**다. 기본값에 실제 개인정보를 절대 넣지 말 것
- 이관 시 원본의 실제 이름·휴대폰·이메일·회사 주소·팩스를 전부 예시값으로 교체했다
  (`홍길동 / 010. 0000. 0000 / hong@example.com` 등)
- 실제 정보는 사용자가 화면에서 입력하면 그 브라우저의 localStorage에만 저장되고 어디에도 전송되지 않는다
- 기본값을 다시 손댈 때 실제 정보를 넣지 않도록 주의

## 구현 메모
- QR 생성: qrcode-generator 1.4.4, zip: JSZip 3.10.1 — 둘 다 CDN 대신 HTML 안에 내장(오프라인 동작)
  갱신: `npm pack <패키지>` 로 받아 `<!-- 내장 라이브러리 -->` 블록 교체
- 아티팩트 버전은 `claude.use("downloads")` 를 썼지만, 이 저장소 버전은 일반 브라우저 다운로드(`saveBlob`)로 교체
- SECO 로고는 CI 원본에서 뽑은 벡터 윤곽(`CI` 상수)을 그대로 채움(evenodd)
- 글자·테두리는 캔버스에 래스터라이즈 후 `extrudeGrid()` 로 watertight 입체 생성
- 판은 `prismWithHoles()` + earcut 축약판으로 둥근 모서리와 원형 구멍을 매끈하게 처리
- QR은 래스터가 아니라 모듈(칸) 단위 격자로 따로 돌출 → 삼각형 수 대폭 감소
- QR은 "판 색이 어두운 칸"이 되는 음각 방식이라 판은 반드시 어두운 색으로 출력해야 인식된다

## 2026-11-06 수정 — 카드 가로 86 → 95mm

정렬을 맞추고 나니 글자가 QR에 바짝 붙어 답답했다. 가로만 약 10% 늘렸다.

- `CW` 86 → 95 (세로 `CH` 54는 그대로). 100% 기준 **95 × 54mm**
- 기하 계산에 박혀 있던 86 / 54 리터럴을 전부 `CW` / `CH` 로 바꿨다
- **QR 크기의 한계가 가로에서 세로로 넘어갔다.** 이전에는 글자 폭이 QR을 막아
  42.35mm였는데, 이제는 카드 높이(= CH - 받침대 - 위아래 여백)가 한계라 45.33mm.
  `qrMaxSide()` 가 그 값을 계산한다
- 글자 최대 폭 `textMaxW()` 는 그 QR 왼쪽에서 `QR_TEXT_GAP`(2.5mm) 떨어진 지점까지.
  고정 상수 `TW0` 는 없앴다
- 결과적으로 글자와 QR 사이에 약 6mm 여백이 생긴다. 점 줄은 그대로 글자 끝에 맞는다

### 검증 (2026-11-06)
이정문 / 책임연구원 / 전동화구동시스템개발1팀, 150% 기준:
- 카드 143 × 81mm, QR 53×53칸 · 한 칸 **0.93 → 1.11mm** (인식 여유 증가)
- QR 링 왼쪽 45.72 / 팀 글자 끝 39.80 / 마지막 점 바깥 39.50
  → 글자와 점은 여전히 정렬(차 0.3mm는 렌더 artifact), 글자~QR 여백 5.92mm
- STL 생성 정상, 콘솔 오류 없음

### 주의
카드가 넓어졌으므로 **기존에 출력한 받침대는 맞지 않는다.** 받침대도 다시 뽑아야 한다.

## 2026-11-06 수정 — 글자 끝 / 점 / QR 왼쪽 끝 정렬

가로 명함에서 세 지점을 한 수직선에 맞췄다.

- 글자 3줄(이름·직급·팀)의 **실제 렌더 폭**을 `textW()` 로 재서 가장 넓은 줄을 정렬선으로 삼는다
- 마지막 점의 바깥쪽이 그 선에 오도록 `pitch` 를 계산한다 (이전에는 고정 폭 TW 기준이라 글자보다 튀어나왔다)
- QR은 오른쪽(86-LM)에 고정한 채 왼쪽으로 늘려 그 선에 닿게 한다. `QR_S` 가 고정값에서 가변으로 바뀌었다
- **순환 참조 주의**: 예전에는 `TW = QR_OUT[0]-2.5-LM` 이라 QR 폭이 글자 크기를 바꿨다.
  QR 폭이 글자 폭에 따라 변하게 되면서 서로 물리므로, 글자 크기 계산용 폭은
  상수 `TW0`(=39.5mm, 기준 QR 36mm일 때의 값)으로 고정했다
- 글자가 짧으면 QR이 과하게 커지므로 세로 여백 `MIN_VM`(2mm)에서 멈춘다

### 검증 (2026-11-06)
이정문 / 책임연구원 / 전동화구동시스템개발1팀 기준, 미리보기에서 mm로 측정:
- QR 링 왼쪽 40.32 / 팀 글자 끝 39.92 / 마지막 점 바깥 39.65 → 한 선에 정렬
  (남은 0.4~0.7mm 차이는 미리보기의 그림자·안티앨리어싱이고 실제 좌표는 같다)
- 겹침 없음, STL 생성 정상, 콘솔 오류 없음

## 2026-11-06 수정 — 점 개수 8 → 7

점 줄의 개수를 텍스트 폭에서 계산하던 것(`round((TW-2*HOLE_R)/5.4)+1`, 항상 8)을
상수 `HOLE_N=7` 로 바꿨다. 간격 `pitch` 는 그대로 텍스트 폭에 맞춰 균등 분배된다.
개수를 다시 바꾸려면 `HOLE_N` 값만 고치면 된다.

### 검증 (2026-11-06)
- 미리보기에서 구멍(투명 픽셀) 개수를 세어 배율 100/120/150% 모두 7개 확인
- `1_base.stl` 삼각형 1,612 → 1,432 (구멍 하나 분량 180개 감소)
- STL 4종 바이너리 구조·치수 정상, 콘솔 오류 없음
