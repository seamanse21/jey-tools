# 와이파이 QR 액자 — 작업 메모

원본: Claude 대화 아티팩트 "와이파이 QR 액자" (2026-11-03) → 이 저장소로 이관.

## 현재 사양
- 입력: SSID / 비밀번호 / 보안방식(WPA·WEP·없음) / 숨김 네트워크 → `WIFI:T:..;S:..;P:..;H:true;;` 문자열
- 명판: 가로 60~180mm, 바닥판 두께 1.6~5mm, QR 돌출 0.4~2mm
- 옵션: 액자 테두리(2.4mm), 상단 걸이 구멍 3개(Ø5, 좌=8mm·중앙·우=W-8mm, 상단 여유 12mm), QR 가운데 Wi-Fi 부채꼴 아이콘, 하단 안내 문구 2줄
  (1줄은 직접 입력, 2줄은 `Wi-Fi : <SSID>` 형식으로 자동 생성)
- 아이콘을 넣으면 QR 오류정정 등급이 자동으로 H로 올라감(약 30% 손상까지 복구)
- 출력물: zip 안에 `wifi_plate_all.stl` / `_base.stl` / `_relief.stl` 3개. QR 이미지 PNG 따로 저장 가능
- QR 한 칸이 2mm 미만이면 통계 칸이 경고로 바뀜

## 구현 메모
- QR 생성: qrcode-generator 1.4.4 (CDN)
- 글자·아이콘은 캔버스에 래스터라이즈 후 가로 런(run)을 사각형으로 묶어 돌출 박스로 변환
- 걸이 구멍은 `holeCell()` 이 사각 셀 + 원형 관통으로 측벽까지 만들어 매니폴드 유지
- STL은 바이너리, Y축을 뒤집어(`H - y`) 프린터 좌표로 변환
- zip은 무압축(store) 방식으로 직접 생성
- 아티팩트 버전은 `claude.use("downloads")` 를 썼지만, 이 저장소 버전은 일반 브라우저 다운로드(`saveBlob`)로 교체함
- qrcode-generator 1.4.4(MIT)를 CDN 대신 HTML 안에 통째로 넣음 → 인터넷 없이도 동작.
  갱신하려면 `npm pack qrcode-generator` 로 받은 `package/qrcode.js` 내용으로 HTML 안의 `<!-- QR 생성 라이브러리 내장 -->` 블록을 교체
- 글꼴만 Google Fonts에서 불러옴. 오프라인이면 시스템 글꼴로 자동 대체되고 기능에는 영향 없음

## 2026-11-05 수정 — 필라멘트 색 선택기

미리보기 색을 CSS 변수(`--plate`/`--relief`)로 고정해 두던 것을 사용자가
고르게 바꿨다. 흰 바닥 + 빨간 글씨처럼 실제로 뽑을 조합을 출력 전에 본다.

- 색 입력 `#c_plate`(바닥판) / `#c_relief`(글자·QR), `draw()` 가 이 값을 쓴다
- 고른 색은 localStorage(`wifiplate.colors.v1`)에 저장돼 새로고침해도 남는다
- 출력 안내의 색 견본(`#sw1`/`#sw2`)도 고른 색을 따라간다.
  이전에는 흰색·검정으로 하드코딩돼 있었다
- **STL에는 색 정보가 없다.** 미리보기 전용이라는 안내를 화면에 적어 두었다

### 검증 (2026-11-05)
- 흰색(#ffffff) + 빨강(#c8102e) 지정 → 캔버스 주요 색이 정확히 그 두 값으로 나옴
- 출력 안내 견본 두 개가 같은 색으로 갱신됨
- 새로고침 후에도 선택한 색 유지
- STL 생성 정상, 콘솔 오류 없음

## 2026-11-05 수정 — 배치 변경 / 글자 크기

- **QR 위에 장소 이름, QR 아래에 와이파이 이름**으로 배치를 바꿨다.
  이전에는 둘 다 QR 아래에 2줄로 들어갔다.
  장소 이름은 `LABEL_SCALE` 과 별개로 상한 9mm를 줘서 제목처럼 크게 나온다
- 하단 글자 크기를 20% 키웠다. `LABEL_SCALE` 상수 하나로 조절한다
  (1.0 = 이전 크기). 판 높이도 같은 비율로 늘어난다
- 장소 이름을 비우면 제목 띠가 통째로 사라지고 판이 그만큼 짧아진다
- 걸이 구멍을 끄면 제목이 판 맨 위에 붙지 않도록 `tGap` 만큼 여유를 준다

### 검증 (2026-11-05)
미리보기 캔버스의 잉크 띠 위치를 mm로 측정해 확인:
- 장소명+SSID: 제목 16.1~22.1 → QR 35.4~117.4 → SSID 127~132.6 (판 137mm)
- 장소명 비움: 제목 띠 없음, 판 137 → 123mm
- 긴 한글 장소명(13자): 폭 자동 축소로 테두리 안에 들어감
- 걸이 구멍 끔: 제목이 8.5mm부터 시작, 판 130mm
- 글자 크기: 변경 전 글자블록 12.9mm → 후 15.7mm (실측 +22%)
- 네 경우 모두 STL 생성 정상, 콘솔 오류 없음

## 2026-11-05 수정 — 연결 실패 원인 대응

출력물로 테스트했을 때 QR은 읽히는데 연결이 실패하는 사례가 있어 네 가지를 고쳤다.

- **앞뒤 공백 제거**: SSID·비밀번호를 `trim()` 한 뒤 QR에 넣는다. 이전에는 공백이
  그대로 들어갔는데 명판 글자는 `trim()` 된 값을 쓰고 있어서, 공백이 들어가도
  인쇄물로는 확인할 방법이 없었다. 가장 유력한 실패 원인이었다.
  공백을 지웠을 때는 화면에 경고를 띄워 사용자가 알 수 있게 했다
- **역슬래시 이스케이프**: `esc()` 정규식이 `[\;,:"]` 로 되어 있어 역슬래시가
  빠져 있었다. `[\\;,:"]` 로 고쳐 비밀번호의 `\` 도 제대로 이스케이프된다
- **WPA3 전용 옵션 추가**: 보안 방식에 `T:SAE` 를 선택할 수 있게 했다.
  WPA3 전용 공유기는 `T:WPA` 로는 연결이 거부될 수 있다
- **QR 내용 표시**: 실제로 인코딩되는 `WIFI:...` 문자열을 화면에 띄운다.
  비밀번호는 가려 두고 "보기" 를 누르면 함께 드러난다. 연결이 안 될 때
  이름의 대소문자·공백을 눈으로 대조할 수 있다

도구 화면에 **출력하기 전에 — 꼭 먼저** 절차를 넣었다.
이름 대조 → 폰에서 네트워크 지우기 → 화면 QR로 연결 확인 → 그 다음 출력.
몇 시간짜리 재출력을 막는 게 목적이다.

### 검증 (2026-11-05)
- 정상 입력 / SSID 뒤 공백 / 비번 앞뒤 공백 → 모두 공백 없는 동일 문자열로 인코딩, 경고 표시 확인
- WPA3 전용 선택 시 `T:SAE` 로 인코딩 확인
- 비밀번호에 `\` 와 `;` 가 섞인 경우 각각 `\\`, `\;` 로 이스케이프 확인
- 보기/숨김 토글 시 표시 문자열이 따라 바뀜, STL 생성 정상, 콘솔 오류 없음

## 검증 (2026-11-03, 헤드리스 크롬)

## 16진수로 읽히는 비밀번호 (2026-11-10)

헬스장에서 "연결할 수 없음", 손으로 치면 접속됨. 오타는 아니었다.

`WIFI:` 규격에서 **숫자와 A~F 로만 된 값은 16진수로 해석**해도 되게 되어 있다.
비밀번호 `12345678` 이 바이트 `0x12 0x34 0x56 0x78` 로 읽히면 당연히 틀린다.
헬스장·카페 비밀번호는 숫자만인 경우가 흔해서 걸리기 쉽다.

- `looksHex()` 로 판별해 `wrapHex()` 가 `P:"12345678";` 처럼 따옴표로 감싼다
- 이름(SSID)도 같은 규칙을 적용한다
- 감쌀 때는 화면에 왜 그랬는지 적는다

### 현장 진단용 QR 4종
원인이 하나가 아니라서, 화면에서 바로 스캔해 가려내도록 QR 4개를 띄운다.
출력 전에 현장에서 스캔하면 어느 것이 연결되는지로 원인을 알 수 있다.

| | 되면 원인 |
|---|---|
| A 지금 설정 | — |
| B 따옴표 없이 | 읽는 쪽이 따옴표를 지원하지 않음 |
| C WPA3(SAE) | 공유기가 WPA3 전용 |
| D 숨김 | 이름을 숨긴 네트워크 |
| 전부 실패 | 이름이 실제와 다름 / 로그인 창 뜨는 게스트망 |

`wifiString(opt)` 에 `{sec, quote, hidden}` 을 넘겨 변형을 만든다.
`showRaw()` 의 비밀번호 가리기도 `wrapHex` 기준으로 맞춰야 한다 (안 그러면
따옴표 붙은 값과 문자열이 안 맞아 가려지지 않는다).
