# 릴스 만들기 — 작업 메모

## 어떻게 만드나
HTML 애니메이션을 **프레임마다 시간을 직접 넣어** 캡처하고 ffmpeg 로 묶는다.

```
node render.js know-template.html kimchi.mp4 15
```

결과는 **1080×1920 · H.264 · 30fps**. 인스타 릴스 규격 그대로다.

## 핵심 규칙 — seek(t)
템플릿은 반드시 전역 `seek(t)` 함수를 가져야 한다. `t` 는 초.
**CSS 애니메이션이나 `requestAnimationFrame` 을 쓰면 안 된다.** 캡처가 실시간보다
느려서 프레임이 어긋난다. 모든 움직임을 `t` 로부터 계산해 그린다.

## 인스타 릴스에서 지켜야 할 것
- **아래 약 450px 는 캡션·오디오 바가 덮는다.** 중요한 글자를 두지 않는다
- 오른쪽 약 200px 도 버튼이 가린다
- **첫 1초 안에 훅이 다 읽혀야 한다.** 0.5초 안에 글자가 멈추도록 맞춘다
- 소리는 넣지 않는다. 인스타 앱에서 유행 음원을 얹는 쪽이 도달에 유리하다

## 글꼴
`render.js` 가 `tools/fonts/fonts.css` 를 읽어 경로를 절대 경로로 바꾼 `_fonts.css` 를
옆에 만든다. 템플릿은 그걸 불러온다. `_fonts.css` 는 커밋하지 않는다.

## 템플릿 두 가지
기사에 따라 골라 쓴다.

| 템플릿 | 언제 | 축 |
|---|---|---|
| `know-template.html` | 숫자가 뚜렷한 기사 | 숫자 두 개가 모여 답이 된다 |
| `vocab-template.html` | **숫자가 없는 기사** | 오늘의 낱말과 사자성어 |

숫자가 없는 기사에 숫자 템플릿을 쓰면 억지스러워진다. 반대도 마찬가지다.

## 장면 구성 — know-template
숫자가 있는 기사에 잘 맞는다.

| 구간 | 장면 | 하는 일 |
|---|---|---|
| 0~2.6초 | 사진 + 질문 | **훅.** 질문으로 멈춰 세운다 |
| 2.6~5.7초 | 숫자 ① | 큰 숫자가 튀어나온다 |
| 5.7~8.7초 | 숫자 ② | 같은 리듬 반복 |
| 8.7~11.3초 | 합치기 | 두 숫자가 모여 답이 된다 |
| 11.3~13.4초 | 확장 | 연도를 세어 올린다 |
| 13.4~15초 | 마무리 | 마스코트 + 받는 법 |

숫자가 없는 기사면 이 뼈대가 안 맞는다. 그때는 다른 템플릿이 필요하다.

## 사진
`photo.jpg` 를 템플릿 옆에 두면 첫 장면 배경으로 쓴다.
`tools/issues/img/` 에서 그 날짜 사진을 복사해 쓴다. 커밋하지 않는다.

## 장면 구성 — vocab-template
숫자가 없는 기사용. 우리 강점인 어휘를 축으로 삼는다. **저장률이 더 높을 형태다.**

| 구간 | 장면 | 하는 일 |
|---|---|---|
| 0~2.6초 | 사진 + 질문 | 훅 |
| 2.6~7.0초 | **오늘의 낱말** | 글자가 뜨고 형광펜이 그어진다. 뜻과 예문까지 |
| 7.0~10.2초 | 기사 한 조각 | 연도 먼저, 문장은 뒤에. 낱말을 다시 강조 |
| 10.2~13.4초 | **오늘의 사자성어** | 한자 네 글자가 0.16초 간격으로 떨어진다 |
| 13.4~15초 | 마무리 | 마스코트 + 받는 법 |

낱말 장면이 4.4초로 가장 길다. 여기가 저장을 부르는 자리이기 때문이다.
