# 사구회 관리 사이트 — 구현 메모

사용 설명은 `README.md`. 이 문서는 나중에 손볼 때 읽을 구조·결정 기록이다.

## 설계 결정

**왜 서버 프레임워크를 안 썼나.** 나스(Synology Web Station)에 폴더째 올려 두면 끝나야 한다는 조건이
제일 컸다. DB·빌드·패키지 설치가 들어가면 나스 사정이 바뀔 때마다 손이 간다.
그래서 정적 HTML + `api.php` 한 장 + `data/*.json` 구조로 갔다.
외부 라이브러리는 하나도 안 쓴다 (저장소 공통 규칙).

**저장 위치를 자동으로 고른다.** `store.js` 가 켜질 때 `api.php?ping=1` 을 한 번 때려 본다.

| 응답 | 모드 | 저장 위치 | 사진·영수증 |
|---|---|---|---|
| `{ok:true}` | server | 나스 `data/*.json` | `photos/`, `receipts/` 에 실제 파일 |
| 그 외 (404·PHP 꺼짐·`file://`) | local | 브라우저 localStorage | 1100px 로 줄여 data URL |

PHP 가 없어도 화면이 다 뜨고 눌러볼 수 있다. 미리보기·시연용으로 쓸모가 있어서 남겼다.

**초기 자료는 `seed/seed.json` 하나로.** 자료가 아직 없을 때 `api.php` 가 이 파일에서 해당 부분을
꺼내 `data/` 에 심고 돌려준다. 클라이언트에 초기화 분기를 두지 않으려고 서버 쪽에 뒀다.
처음엔 `seed/<store>.json` 으로 쪼갰는데, 없는 파일마다 404 가 찍혀서 한 파일로 합쳤다.

**공개 저장소라 실제 기록은 커밋하지 않는다.** `data/`, `photos/`, `receipts/` 는 `.gitignore` 에 있다.
`seed/seed.json` 의 회칙 초안에도 회원 실명을 넣지 않았다 (제3조는 "9명으로 한다" 로만).
실명이 든 `data/members.json` 과 회칙은 Jey 에게 전달한 zip 안에만 있다.

## 파일

```
index.html          껍데기 (상단바 + 탭 + 모달/토스트 자리)
assets/store.js     저장 계층. 모드 판정, 읽기/쓰기(350ms 디바운스), 업로드, 이미지 축소, 백업
assets/ui.js        h() DOM 헬퍼, 금액·날짜 포맷, 모달, 토스트, 첨부 위젯, 복사/다운로드
assets/app.js       해시 라우터(#/dues 등), "나" 선택, 모드 배지, 백업 버튼
assets/page-*.js    화면 5개. 각각 window.PAGES[이름] = function(view, params) 로 등록
api.php             ping / store 읽기·쓰기 / 파일 업로드
seed/seed.json      첫 설치용 초기 자료 (설정 + 회칙 초안)
```

ES 모듈이 아니라 평범한 `<script>` 다. `file://` 로 열어도 돌아가야 해서 그렇게 했다.

## 자료 구조

```jsonc
settings  { monthlyDue, kmPerLiter, fuelPrice, startYear, chairman, treasurer, dueYearly:{"2006":30000} }
members   [ { id:"m1", name, active, joinedAt } ]
rules     { articles:[{id,title,body,since}], history:[{id,at,reason,by,snapshot:[...articles]}] }
history   { meetings:[{ id, date, season, place, attendees:[mid], memo, spend,
                        photos:[{name,url}], agendas:[{id,title,body,proposer,votes:{mid:"찬성"},status}] }] }
dues      { years: { "2026": { "m1": { "3": 50000 } } } }      // 금액 그대로 저장, 0 이면 키를 지움
expenses  { seq, requests:[{ id,no,applicantId,meetingId,date,status,statusNote,memo,
                             trips:[{mode,note,roundTrip,amount,receipts,km,toll,tollReceipts,kmPerLiter,fuelPrice}],
                             items:[{label,amount,receipts}] }] }
```

회비는 **금액**으로 저장한다 (bool 아님). 부분 납입과 연도별 회비 변동을 담으려면 이래야 했다.
회칙 개정 이력은 diff 가 아니라 **전문 스냅샷**이다. 9명짜리 모임 규모에서는 이게 제일 안 헷갈린다.

## 계산 규칙

- 자차 유류비 = `총 운행거리 ÷ 연비기준(기본 10km/L) × 유가단가`, `Math.round`
- 안건 자동 판정 = 찬성 > 참석자 ÷ 2 면 가결, 반대 ≥ 찬성이면 부결, 나머지는 보류. 손으로 덮어쓸 수 있다
- 회비 "미납" = **지난 달까지만** 센다. 올해면 이번 달까지, 지난해면 12개월, 내년이면 0.
  (연말까지의 미래분을 미납으로 세면 11월에 미납이 500만원으로 찍혀서 쓸모가 없었다)

## 손봤던 버그 (같은 실수 반복 방지)

1. **`[hidden]` 이 안 먹던 모달.** `.modal{display:flex}` 가 `[hidden]` 의 `display:none` 을 이겨서,
   닫힌 모달이 화면 전체에서 클릭을 가로채고 있었다. `[hidden]{display:none!important}` 로 해결.
2. **`change` 이벤트 의존.** 입력칸을 `onchange` 로 받으면 포커스가 빠져야 값이 들어간다.
   모바일에서 숫자 입력하고 바로 탭을 옮기면 값이 날아간다. 글자·숫자 입력은 전부 `oninput` 으로 바꿨다
   (셀렉트·체크박스만 `change`). 저장은 어차피 350ms 디바운스라 부담 없다.
3. **회비 칸 토글이 한 방향으로만.** 클릭 핸들러가 렌더 시점 금액을 클로저에 가둬 놓고,
   `refresh()` 는 버튼을 새로 만들지 않아서 두 번째 클릭이 먹지 않았다. 핸들러 안에서 현재 값을 다시 읽게 고쳤다.
4. **합계 상자 초기화 순서.** `drawTrips()` 가 아직 만들어지지 않은 `totalBox` 를 건드려 터졌다.
   상자를 먼저 만들고 자리에만 나중에 붙인다.
5. **한글 파일명 다운로드.** Chromium 이 비ASCII `download` 속성을 버리고 `download` 라는 이름으로
   저장해서, 백업 파일명을 `sagoohoe-backup-YYYY-MM-DD.json` 으로 바꿨다.

## 검증

Playwright 로 PHP 띄운 상태(31개)·PHP 없는 상태(6개)·업로드(6개)를 돌렸고 전부 통과했다.
확인한 것: 저장 모드 판정, 회비 칸 토글/월 일괄/금액 직접 입력/서버 파일 반영, 모임·참석자·안건 투표
가결·부결, 자차 유류비 계산(420km → 71,400원), 영수증 없는 제출 차단, 승인→지급완료 상태 흐름,
회칙 개정 확정과 이력 전문, 사진·영수증 업로드와 실제 파일 생성, 백업 내려받기,
390px 폭에서 가로 넘침 0, 다크 모드.

테스트 스크립트는 세션 임시 폴더에 있었고 저장소에 남기지 않았다.
다시 돌리려면 `php -S 127.0.0.1:8777 -t .` 띄우고 Playwright 로 같은 흐름을 밟으면 된다.

## 나스에 실제로 올리면서 겪은 것 (DSM 7)

**QuickConnect 로는 Web Station 사이트가 안 열린다.** QuickConnect 는 DSM 관리 화면만 중계한다.
집 안에서는 나스 IP(`192.168.0.210`), 밖에서는 DDNS(`seamanse.synology.me`) 로 들어가야 한다.

**`.php` 만 500 이 났던 이유.** Web Station → 웹 서비스 → 기본 서비스의 PHP 가
"구성되지 않음" 이었다. PHP 8.2 패키지는 깔려 있었는데 서비스에 연결만 안 된 상태.
연결하고 저장하면 잠시 503(Apache 가 PHP-FPM 을 아직 못 잡음)이 나는데, 재부팅하면 풀린다.

**`phpcheck.php` 가 실행 계정을 잘못 보고했다.** Synology PHP 는 `posix_*` 함수가 막혀 있어
`get_current_user()` 로 넘어가는데, 이건 프로세스 사용자가 아니라 **스크립트 파일의 주인**을 돌려준다.
그래서 `seamanse` 로 찍혔지만 실제 웹서버 계정은 `http` 였다. 이것 때문에 엉뚱한 계정에
권한을 주느라 한 바퀴 돌았다. 권한 문제를 볼 때는 계정 이름을 믿지 말고
**`is_writable()` 결과와 실제 쓰기 테스트**로 판단하는 게 맞다.

**폴더 권한.** File Station → 폴더 우클릭 → 속성 → 권한 → 생성 에서 사용자 `http` 에
읽기+쓰기를 주고, **"이 폴더, 하위 폴더 및 파일에 적용"** 을 반드시 켜야 한다.
관리자 계정(seamanse 등)으로 규칙을 만들면 "관리자라 적용되지 않는다"는 안내가 뜨고 실제로 안 먹는다.

## 접속 잠금 — 기본 인증에서 앱 안 로그인으로

처음엔 `.htaccess` 기본 인증으로 갔다. 앱 코드를 안 건드리고 정적 파일까지 한 번에 막혀서
가장 깔끔했고, Apache 를 띄워 전부 검증까지 했다. **그런데 실제로 단톡방에 링크를 뿌리니
친구 폰에서 `Unauthorized` 만 떴다.** 카카오톡 내장 브라우저가 서버의 기본 인증 창을
띄우지 못한다. 인스타그램 등 다른 앱 내장 브라우저도 마찬가지다.
링크를 공유해서 쓰는 사이트에 기본 인증은 못 쓴다.

그래서 로그인 화면을 **사이트 안**으로 옮겼다. 구성은 이렇다.

- `data/auth.php` — 아이디와 bcrypt 해시. `include` 하면 `$SG_AUTH` 가 잡힌다.
  JSON 이 아니라 PHP 로 둔 건, 차단막이 혹시 안 먹어도 직접 열었을 때 아무것도 안 나오게 하려고.
- 세션 쿠키 60일. `api.php` 의 `?login=1` / `?logout=1` / `?ping=1`(`auth` 상태 반환).
- `store`·`upload` 는 로그인 필수. 사진·영수증은 **`api.php?file=경로`** 로만 나간다.
- `data/`, `photos/`, `receipts/`, `seed/` 각 폴더에 `Require all denied` 짜리 `.htaccess` 를 깔아
  주소로 직접 열리는 길을 막는다. `api.php` 가 ping 때마다 없으면 다시 만든다(자가 복구).
- 로그인 실패는 1초 지연 + 같은 IP 10회 실패 시 10분 차단(`data/_login_fail.json`).

`index.html` 과 `assets/*` 는 로그인 없이도 받아진다. 민감한 내용이 없고,
실제 자료는 전부 `api.php` 를 거치기 때문에 문제되지 않는다.

Apache + Playwright 로 검증: 카카오톡 UA 환경에서 로그인 화면 정상 표시,
로그인 전 회원 이름 노출 없음, `data/*.json`·`data/auth.php`·`seed/` 직접 접근 403,
`api.php?store=` 401, 틀린 비밀번호 거부, 로그인 후 회비 저장, 새로고침 후 세션 유지,
사진 업로드 후 `api.php?file=` 로 실제 렌더(naturalWidth>0), 비로그인 세션에서 같은 사진 401,
로그아웃 후 다시 로그인 화면.

## 고칠 때 (앞으로 계속 수정할 예정)

브라우저가 옛 `assets/*.js` 를 들고 있으면 "고쳤는데 그대로"가 된다.
그래서 `index.html` 이 자산을 `?v=1` 로 불러온다. **자산을 고칠 때마다 이 번호를 올리고
`index.html` 도 같이 올려야 한다.** 번호만 바뀌면 브라우저가 새로 받는다.

나스에 올릴 때는 바뀐 파일만 덮어쓴다. `data/`, `photos/`, `receipts/` 는 **절대 덮어쓰지 않는다**
— 거기에 실제 기록이 들어 있다. `.htaccess` 와 `.htpasswd` 도 건드리지 않는다 (잠금이 풀린다).

## 권한 — 운영진과 회원

`data/auth.php` 에 계정이 두 벌 들어간다(`admin`, `member`). 로그인할 때 어느 쪽인지
가려 세션에 역할을 넣는다. 화면에서 버튼을 감추는 것만으로는 개발자도구로 뚫리므로
**서버에서 쓰기를 막는 쪽이 본체**다.

- `settings` · `members` · `rules` · `dues` — 쓰기는 운영진만 (`sg_need_admin`)
- `history` — 회원이 보내면 `sg_history_ok()` 로 **사진 말고 바뀐 게 있으면 거절**.
  모임 추가·삭제도 막는다. 각 모임에서 `photos` 만 떼고 JSON 을 비교한다
- `expenses` — `sg_expenses_ok()` 로, 회원은 상태를 `작성중`·`접수` 로만 바꿀 수 있고
  이미 `승인`·`지급완료` 된 건은 한 글자도 못 고친다. 지우는 것도 `작성중` 일 때만

회원 계정은 9명 공용이라 서버가 "누가 쓴 신청인지" 는 구분하지 못한다.
그래서 "남의 신청은 못 고침" 대신 "처리된 신청은 못 고침" 으로 규칙을 잡았다.

읽기는 둘 다 전부 허용한다. 회비·회칙·모임 기록은 회원이 봐야 하는 내용이고,
가리는 쪽이 오히려 모임 운영에 방해가 된다.

검증(Apache + Playwright): 회원 계정으로 settings·members·rules·dues 쓰기 403,
히스토리 장소 변경 403 / 사진만 추가 200 / 모임 추가 403,
정산 새 신청 200 · 제출 200 · 스스로 승인 403 · 승인된 건 수정 403, 운영진은 전부 200.
화면에서는 회원일 때 설정 탭·백업 버튼·모임 추가·회칙 편집·승인 버튼이 사라지고
회비 칸이 잠기며, 주소로 설정에 들어가도 막힌다. 운영진 화면은 전과 같다.

## 히스토리 구조 (운영진이 만들고 회원이 사진을 붙인다)

모임 생성이 "빈 카드를 만들고 펼쳐서 채우기" 였는데, 과거 모임을 쭉 입력하기엔
불편해서 **만들기 모달**로 바꿨다. 연도·구분·날짜·장소·참석자·메모·지출을 한 번에 받는다.

`meeting.year` 를 따로 둔다. 2006~2010 쯤 모임은 날짜가 기억나지 않는 경우가 있어
**연도만으로도 등록**되게 했다. 묶음과 정렬은 `year` 우선, 같은 해 안에서는 `date` 순.
`date` 를 넣으면 `year` 를 자동으로 맞춘다.

회원 화면은 입력칸을 비활성화해서 보여주던 걸 **읽기 전용 요약**으로 바꿨다.
회색 입력칸이 잔뜩 깔리는 것보다 낫고, 사진 올리는 자리가 눈에 띈다.

사진에 `by`(올린 사람)와 `at`(올린 날)을 같이 적는다. 이름은 헤더의 "나" 선택값이다.
9명이 계정 하나를 같이 쓰므로 서버는 누가 올렸는지 모른다. 그래서 삭제 제한
(자기 것만 지움)은 **화면에서만** 거는 약한 규칙이다. 친구 모임 규모에서는 이 정도면 된다.

역할 배지를 누르면 로그아웃된다. 회원으로 로그인한 뒤 운영진으로 바꿀 길이
화면 맨 아래 로그아웃 버튼뿐이라 안 보인다는 말을 듣고 상단으로 올렸다.

## 다크 모드에서 날짜칸이 안 보이던 문제

"새 모임 만들 때 날짜 드롭다운 화살표가 안 보여서 못 써먹었다" 는 말을 듣고 찾았다.
`input[type=date]` 의 달력 아이콘과 `select` 화살표는 브라우저가 그리는데,
`color-scheme` 을 지정하지 않으면 **밝은 테마 기준(짙은 글리프)** 으로 그려서
어두운 배경에서 거의 안 보인다.

`:root` 에 `color-scheme:light`, 다크 블록에 `color-scheme:dark` 를 넣어 해결했다.
스크롤바와 기본 폼 색까지 같이 맞춰진다. 보강으로
`input[type=date]::-webkit-calendar-picker-indicator` 에 `filter:invert(1)` 도 걸어 뒀다.

한때 연·월·일 드롭다운 세 개로 바꿨다가, 달력과 직접 입력이 둘 다 되는 게 낫다고 해서
`input[type=date]` 로 되돌리고 옆에 **연도 드롭다운**을 따로 뒀다 (날짜를 모르는 옛날 모임용).
날짜를 넣으면 연도가 자동으로 따라간다.

## 파일 올리기 — 버튼을 보이게

기본 `input[type=file]` 은 "Choose Files / No file chosen" 이라는 영어가 뜨고,
고른 뒤에 바로 올라가는지 알 수 없어서 "업로드 버튼이 안 보인다" 는 말을 들었다.
입력칸을 숨기고 **`📷 사진 고르기` 버튼**을 따로 두고, 고른 즉시 한 장씩 올리면서
"올리는 중… 2 / 5장" → "5장 올렸습니다" 를 옆에 적는다. 실패하면 그 자리에 빨갛게 이유를 쓴다.
토스트만 쓰면 놓치기 쉬워서 자리에 남는 글씨로 바꿨다.

회원 화면에서는 "나" 를 고르지 않았으면 올리기 칸 대신 **이름 고르기**를 먼저 띄운다.
사진에 올린 사람이 비는 걸 막으려는 것이다.

## 영상과 끌어다 놓기

**끌어다 놓기** — 파일 입력을 감싼 `.drop` 영역에 dragenter/over/leave/drop 을 달았다.
고르기와 끌어다 놓기가 같은 `take(fileList)` 로 들어간다. dragleave 가 자식 요소에서도
튀어서 테두리가 깜빡이므로 depth 카운터로 센다.

**영상** — 확장자 mp4/mov/m4v/webm/3gp 를 받는다. 사진과 달리 줄이지 않고 원본을 올린다.
썸네일 자리에는 `<video controls preload="metadata" playsinline>` 을 둬서 그 자리에서 재생된다.

`api.php?file=` 에 **Range 응답(206)** 을 넣은 게 핵심이다. 이게 없으면 Safari·iOS 에서
영상이 아예 재생되지 않는다. 206 과 `Content-Range`, `Accept-Ranges` 를 돌려주고
256KB 씩 끊어 보낸다.

**용량 한도** — 진짜 벽은 나스 PHP 의 `upload_max_filesize` / `post_max_size` 다.
Synology 기본값이 2M 인 경우가 흔한데 폰 영상은 수십~수백 MB다. 그래서
`ping` 이 `maxUpload` 를 함께 돌려주고, 클라이언트가 **고르는 즉시** 크기를 재서
"이 나스는 2MB까지" 라고 알려 준다. 서버에서도 `UPLOAD_ERR_INI_SIZE` 와
`$_FILES` 가 통째로 비는 경우(post_max_size 초과)를 잡아 같은 안내를 준다.
`phpcheck.php` 맨 위에도 현재 한도를 찍는다.

로컬(브라우저 저장) 모드에서는 영상을 막는다. data URL 로 넣으면 localStorage 가 터진다.

검증: 끌어다 놓기로 사진 첨부·테두리 강조, mp4 업로드 후 실제 재생(320px·2초 메타데이터
읽힘), Range 요청에 206 과 올바른 Content-Range, 한도를 넘는 5MB 파일에 대해
화면·서버 양쪽에서 한글 안내.

## 모임별 회장 · 총무

`meeting.chairmanId` / `treasurerId` 에 회원 id 로 담는다. 설정의 `chairman`·`treasurer` 는
**이름 문자열**이라, 새 모임을 만들 때 이름으로 id 를 찾아 기본값으로 채운다
(`idByName`). 회장이 바뀌어도 옛 모임 기록은 그대로 남는다.

같이 고친 것: 카드 제목줄이 접었다 펴도 갱신되지 않아, 안에서 날짜·장소·회장을 고쳐도
목록에는 옛 내용이 남아 있었다. `card()` 가 `syncHead()` 를 만들어 본문에 넘기고,
본문의 `saveSoon` 이 저장과 함께 제목줄을 다시 그린다.
